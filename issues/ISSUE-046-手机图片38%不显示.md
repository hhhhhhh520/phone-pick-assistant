# 38% 手机的商品图片永远不显示，且完全静默

> 创建时间: 2026-09-12 | 状态: 🟢已解决（2026-09-13 修复 commit a1e4019，三层归一：前端+模型 @validates+数据源；验证见 PROGRESS「2026-09-13」章节）

## 问题描述

推荐结果卡片中，大量手机**没有图片**（显示默认图标），且**没有任何报错**——无破图图标、无 console 错误、网络面板里**连请求都不发出**。

实测：一次返回 3 张卡片时，DOM 中只有 **1 个 `<img>`**。其中 `X200 Pro` 有图，`X200` 与 `小米14` 无图。

对全库 352 条统计 `imageUrl` 格式：

| 格式 | 条数 | 占比 |
|---|---|---|
| `http(s)` 外链（中关村在线图床） | 169 | 48% |
| **`images\...` 反斜杠（Windows 路径）** | **132** | **38%** |
| `/images/...` 正斜杠 | 43 | 12% |
| 空 | 8 | 2% |

即 **132 条（38%）的手机图片永远无法显示**。

## 出现原因

`frontend/src/components/PhoneCard.tsx:91-99` 的 URL 拼接逻辑，两处缺陷叠加：

```js
const API_BASE = import.meta.env.VITE_API_BASE || 'http://localhost:8002';  // 结尾无斜杠
...
const encoded = url.includes('%') ? url : encodeURI(url).replace(/\+/g, '%2B');
return `${API_BASE}${encoded}`;
```

对反斜杠路径 `images\vivo X200(16GB1TB)_1.jpg`：

1. `API_BASE` 结尾无 `/`，且 `encodeURI` **不会**把 `\` 规范化成 `/`（而是编码为 `%5C`）
2. 拼出 `http://localhost:8002images%5Cvivo%20X200(16GB1TB)_1.jpg`

结果**主机名被吃成 `localhost:8002images`**。在浏览器内按组件相同逻辑复刻，实测：

```
Failed to parse URL from http://localhost:8002images%5Cvivo%20X200(16GB1TB)_1.jpg
```

浏览器拒绝解析 → 请求根本不发出 → `onError` 触发 → `imageError=true` → 静默换成默认图标。这解释了为什么网络面板里看不到失败请求。

（正斜杠的 43 条拼接正确，`http://localhost:8002/images/...` 能正常 200。）

## 解决方案（两个方向都做了）

### 1. 前端容错（`PhoneCard.tsx`）

把 `getFullImageUrl` 从组件内联函数提出来**导出**（便于精确单测），并修正两处：

```ts
const path = url.replace(/\\/g, '/');                            // 反斜杠归一
const normalizedPath = path.startsWith('/') ? path : `/${path}`; // 保证以 / 开头
const base = apiBase.replace(/\/+$/, '');                        // 基址去尾斜杠
return `${base}${encoded}`;                                      // 二者之间恰好一个斜杠
```

顺带把 `apiBase` 做成默认参数，使"基址带尾斜杠"这种情况可被单测覆盖。

### 2. 数据归一（治本）

`backend/data/fix_image_urls.py` **早就写好但从没跑过**（DB 里 132 条仍是反斜杠）。
本次执行（执行前已备份到 `backups/phones.db.bak-before-ISSUE046-20260913`，`backups/` 在 `.gitignore` 内）：

```
Total fixed: 132
```

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 残留反斜杠 | 132 | **0** |
| `/images/` 开头 | 43 | **175**（43+132） |
| 外链 | 170 | 170 |
| 空 | 8 | 8 |

（353 = 175 + 170 + 8 ✓）

⚠️ 该脚本直接运行会 `ModuleNotFoundError: No module named 'backend.models'`——
它 `from backend.models.domain import ...` 但没把项目根加进 `sys.path`。
需要 `PYTHONPATH=. python backend/data/fix_image_urls.py` 才能跑起来。

### 3. 可持续性：数据源也曾是脏的（审查发现，已补）

活库 patch 完还不算完——**`backend/data/phones_export.json` 是被 git 跟踪的灾难恢复数据源**，
而它当时那 132 条仍是反斜杠；恢复脚本 `scripts/import_phones_json.py:68` 是裸写
`image_url=row.get("imageUrl")`。**按文档做一次 DB 恢复，132 条会全部复发。**

所以又补了两层：

1. **模型层归一化**——`backend/models/domain.py` 的 `Phone` 加 `@validates("image_url")`，
   覆盖**所有**写入路径（含恢复脚本）。放在这里的理由就是：只修某一个写入点治不了别的
2. **数据源归一**——`phones_export.json` 里 132 条 `images\x.jpg` → `/images/x.jpg`
   （逐值替换，diff 恰好 132 行增删，无重排）

## 验证方式

**单元测试**（`frontend/src/test/PhoneCard.test.tsx`，新增 5 条 `describe('getFullImageUrl')`）：
用 **id=1482 的真实值** `images\OPPO A32（8GB128GB全网通）_1.jpg` 断言
URL 可被 `new URL()` 解析、pathname 以 `/images/` 开头、不含 `%5C`；
另覆盖"基址带/不带尾斜杠""反斜杠/正斜杠/无前导斜杠"三种路径形态、
外链原样返回、空值返回 null、以及 `+`→`%2B` 的既有行为。

**关于"先证明会红"——我第一次的说法不够严谨，特此更正**：
当时看到的是"5 条全红"，但那是因为函数**还没导出**——import 拿到 `undefined`，
直接抛 `getFullImageUrl is not a function`，把这个错误当成了红。
审查者保留导出、**只回退函数体**后复测，真实情况是：

| 用例 | 只回退函数体时 | 判别力 |
|---|---|---|
| 反斜杠归一化 | ❌ 红 | **真守卫** |
| 基址与路径之间恰好一个斜杠 | ❌ 红 | **真守卫** |
| 外链原样返回 / 空值 null / `+`→`%2B` | ✅ 绿 | 守的是**别的**回归，不是这条 |

教训：**"红"必须来自被测量的行为，不能来自 import 错误**。

**后端新增**（`tests/test_image_url_normalization.py`，11 条）：
`Phone(image_url=...)` 的归一化（含中文/全角括号/外链/空值）+ **数据源 JSON 无残留反斜杠**。
先证红：修复前 5 红（模型未加 validator、JSON 未清洗）。
后端全量 **846 passed**。

**浏览器 A/B（真实 DB 值）**——决定性证据：

| 记录（DB 原值） | 修复前的拼法 | 修复后的拼法 |

| `images\华为畅享 80（128GB）_1.jpg` | `Failed to parse URL`（主机名被吃成 `localhost:8002images`） | **200** |

"浏览器拒绝解析、请求根本不发出"这一机理被逐字复现（`fetch` 直接抛错，不是 404）。

**端到端**：前端全量 `vitest run` 130 passed（12 文件）；`tsc -b` 通过；
真实推荐流程中带本地图片的卡片 `<img>` 能正常加载（`naturalStatus=200`、`naturalWidth>0`）。

**一个诚实的边界**：**数据归一之后再回浏览器验证就无法隔离反斜杠分支了**——
真实数据里已经没有反斜杠值，前端那条容错分支不会再被触发。
所以该分支的守卫只有单测（用的正是真实历史值），这已经足够；
但"改动后的浏览器渲染"这条证据链在归一化之后是拿不到的。

## 附带发现（本工单范围外）

`frontend/.env.example` 写的是 `VITE_API_BASE=http://localhost:8000`，
而 `PhoneCard.tsx` 的 fallback 是 `http://localhost:8002`，`backend` 实际也跑在 8002。
当前没有 `.env`，所以走 fallback（8002）正常；但**照抄 `.env.example` 建 `.env` 会指向 8000 而连不上**——
与面试助手 ISSUE-007 同一类问题，建议统一。
